# Travel 账户核对

## 定位与取证

1. 通过 Travel OAuth MCP 查现有账户、持有人和权益。逐项核对。姓名有不同译法时，核对 Travel 成员、用户确认和供应商页面上的账户姓名。认领或修改前先排除重复账户和归属歧义。
2. 优先用已授权的只读连接。用户明确授权访问供应商官网时，用 BrowserOS neo 的独立任务标签页，先复用有效会话。需要登录时走供应商正常流程。验证环节只有在现有获授权工具能完成时才自动处理，否则让用户直接在官网完成该步。定时任务遵守自身授权，交互式网站授权不自动延伸到后台。
3. 核对页面显示的余额、观察时间、最近一次合格活动或本周期权益状态。对照供应商现行官方条款。保活基于符合条款且有证据的活动，待入账消费单独保留为未确认。区分官方到期日与从活动日期推导的风险日期。证据只显示日期时保留日期精度。

## 回传与验收

- 交互式点数账户用 `travel_record_loyalty_account`。提供持有人和计划、核实的余额及日期、活动类型、条款版本和无签名来源链接。由 DeepSeek 查重、更新现有账户并回读。优先使用现有业务字段，缺少活动日期字段时写入来源备注。官方到期日未知时留空，推算日期仅进备注。其他权益按其 Travel MCP 契约写入。
- 权益待办按 Travel 仓库的 `docs/AI.md` 使用当前租约、字段白名单、固定请求键和回执协议。租约过期后停止回传。历史回执按原任务 ID 和回传键查询。已结束且不可重开的事项，在用户授权下通过现有业务写入入口登记新证据，并报告两个结果的关联状态。
- `travel_get_task` 查至终态。核对 `changes` 的前值、后值、原因与回读，以及 `unresolved`、`pending_confirmations` 和 `continuation`。同类会话用原工具和原 `session_id` 续问。按当前回执契约分别核实提交、云端验收和账户写回。未知写入先查原请求，不换键重放。

## Bilt 已验证路径

- 从官网登录页选 Email 并提交，保留原登录标签页。邮件主题为 `Your Bilt login link`。用请求发起时间查找本次邮件，核对收件人、发件域、邮件认证结果及 `www.bilt.com` 的直接登录链接。在同一 Neo 浏览器配置的另一个标签页打开并确认，再回原标签页继续。邮件验证后可能要求手机验证码。若 Google Voice 转发已到达但连接器隐去了验证码，由用户在官网输入。
- 已登录时，从个人菜单的 **Your Points** 打开 **Activity**，核对账户名、余额和最近显示为已入账的合格活动。活动页按相对日期显示时，结合页面其他日期和观察日期确认绝对日期。保活条件查 [Bilt 官方条款](https://www.bilt.com/terms)。

Skill 只保存通用步骤。Travel 只接收所需业务事实及不含凭据的来源引用。用户名、邮箱地址、密码、会话凭据、验证码、登录链接、完整会员号和邮件正文留在原渠道，禁止写入 skill、日志、记忆或发给 Travel 和 DeepSeek。交互核对只读访问供应商，仅按用户授权登记核实事实。
